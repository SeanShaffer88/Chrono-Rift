# Environment pass: steampunk dungeon and papercraft town

The approved target is images/environment-steampunk-papercraft-concept.png.
It is a concept, with more detail than this alpha implementation. The game uses
selected CC0 Kenney meshes plus original paper foliage and pipe fittings. Exact
archive versions and licenses are in assets/kenney/ENVIRONMENT_SOURCES.md.

Dungeon decoration uses deterministic batched meshes over the existing collision
grid. Each walkable cell receives exactly one floor variant. Authored opposite
coplanar faces use back culling to avoid flicker. Copper fittings, gauges and small
steam quads occur only beside the bounded set of lit room torches (maximum eight).
They add no blockers and do not consume the gameplay random sequence.

Town terrain keeps the entire buildable area flat, including footprint edges.
Sloped ground and boundary collision sit outside that area. Restored houses use
fitted timber panels, red roofs, cream paper edges and working doors. Foliage has
thick cutout silhouettes baked into one draw surface per tree. Sparse grass hides
under placed pieces and returns when pieces are removed. The natural backdrop
grants no restoration parts. River and placement rules are unchanged.

## Shader Inspector tuning

These shaders support Compatibility and Vulkan Mobile. Each fragment has no
conditional branches. Paper uses one palette fetch, no noise/mask fetches; river
and steam use zero textures. Paper and river are opaque. Steam uses one small
transparent quad per vent, no particles or screen textures.

1. Run the town or dungeon and switch the Scene dock to **Remote**. Select a
   MeshInstance3D. Expand **Material Override** or **Surface Material Override**,
   then **Shader Parameters**. Runtime materials are generated by code, so Remote
   edits are temporary. Duplicate/save a material as .tres for experimentation;
   update the defaults below in source to persist the project's generated look.
2. For town surfaces, paper_surface.gdshader exposes **Tint** (start here),
   **Palette Texture** (keep the source colormap on imported kit models),
   **Vertex Colors** (1 on terrain and baked trees, 0 on authored panels), and
   **Red Roof** (1 only on roof models). Keep the last two at their assigned values.
3. Set **Fiber Strength** to 0 to compare a flat surface, then raise in 0.01 steps;
   default 0.045. **Fiber Scale** defaults to 32 per world meter; lower it toward
   16 for broader grain. Distance derivatives fade fine grain to reduce shimmer.
   Generated values live in scenes/environment/papercraft.gd and the shader.
4. On the town's water MeshInstance3D, river_surface.gdshader exposes **Deep Color**
   and **Shallow Color** for the layered paper bands. Keep their brightness close
   so the stream remains readable. **Flow Speed** defaults to 0.6; set 0 to inspect
   a still pattern, then increase in 0.1 steps. This is a decorative opaque surface,
   not a transparent water simulation. Defaults live in the shader.
5. In dungeon FloorGenerator's generated content, find a WallTorch/VentSteam mesh.
   steam_wisp.gdshader exposes **Steam Color**, **Opacity** (default 0.1; stay at or
   below 0.15 for subtlety), and **Rise Speed** (default 0.45; 0 freezes the pattern).
   Leave Cast Shadow off and the quad small to bound transparent overdraw.
6. Check both walking and overhead views, orbit the camera, and test Android before
   increasing detail. The earlier companion/warning guide remains SHADER_TUNING.md.

## Verification

Run tools/Test-Project.ps1 with the pinned Godot executable. The environment suite
checks deterministic CPU placement plans, exactly one tile per cell, flat core
collision, exterior ridges, bridge rail orientation, grass coverage and paper-tree
geometry budgets. Godot's dummy headless renderer returns identity MultiMesh
transforms, so run tests/test_environment_art.gd with a real renderer as well;
it additionally checks uploaded floor transforms and hidden grass. The existing
Georama suite verifies assembly, preview cancellation, door/interior access and
return behavior. Visual fixtures capture actual restored examples without granting
parts to the shipping game. Shipping exports exclude tests and docs.
